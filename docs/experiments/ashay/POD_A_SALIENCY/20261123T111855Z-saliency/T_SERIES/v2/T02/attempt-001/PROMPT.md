# Appendix A: User-supplied mandatory T02 goal standard

The following is reproduced from the supplied goal-standard attachment. Its requirements are incorporated into the execution and acceptance logic above.

**Set T02’s goal as: establish a complete, evidence-backed account of the forget dataset’s identity, location, expected contents, documented provenance, and availability for explicitly named downstream uses.**

T02 earns success only when **every mandatory acceptance condition below passes**. An unknown, unresolved contradiction, inaccessible required source, or missing required dataset component prevents that success verdict. The executor should still preserve useful work and report the exact blocker.

The standard must also keep its scope honest: T02 establishes dataset provenance and input availability. T03 establishes checkpoint associations; T04 establishes metric meaning. T02 cannot certify those later stages in advance.

**1. Define exactly which dataset or datasets T02 must account for.**

Start from the actual T01 catalog and reviewed configurations. Identify every distinct dataset reference associated with the supplied forget-related runs.

For each reference, record:

- Source artifact ID, version, and exact configuration key or document location.
- Original referenced location.
- Declared purpose: forget training, forget validation, forget testing, retain, mixed, or unresolved.
- Referencing run or candidate, without inventing checkpoint associations.
- Whether it identifies a complete dataset, split, shard, index, cache, or preprocessing output.

**Acceptance:** Every relevant reference in the defined source inventory has a disposition. No reference disappears because it is inconvenient, duplicated, inaccessible, or ambiguous.

The source inventory must itself be explicit. “All references” means all references within that established scope, not an unsupported claim about every file the producing team possesses.

**2. Resolve references to concrete source objects.**

For every required dataset component, establish its actual location using stable identifiers.

Record:

| Required field | Standard |
|---|---|
| Source system | Drive, referenced local filesystem, external repository, or other documented source |
| Exact locator | Stable file/folder ID or fully resolved path |
| Version identity | Immutable revision or other supported content identity |
| Observation | What was actually observed, when, and through which access route |
| Reference binding | Evidence connecting the configuration reference to this object |
| Access state | Metadata visible, content access established, inaccessible, or untested |

A similarly named folder is insufficient. A path appearing in a configuration is insufficient. An accessible replacement dataset is insufficient unless its relationship to the original is established.

**Acceptance:** Every required reference resolves to the intended source object with supporting evidence. Unresolved references remain blockers.

**3. Establish the complete expected membership before declaring completeness.**

Obtain an authoritative manifest or equivalent source documentation describing the expected dataset components.

Distinguish:

- Expected files or shards.
- Observed files or shards.
- Missing members.
- Unexpected members.
- Duplicate objects or aliases.
- Alternative versions.
- Split manifests, indices, and required preprocessing metadata.

A recursively exhausted folder listing establishes what was visible. It does not establish that the producer supplied everything expected.

**Acceptance:** The expected membership is independently justified, and every required component is accounted for. If the expected membership is unknown, dataset completeness remains unknown and this condition fails.

Do not invent a denominator from whatever happened to be found.

**4. Resolve the nine-container uncertainty at the appropriate level.**

Give every previously unopened container an explicit disposition:

- Exact identity and type.
- Whether an existing verified inventory already identifies its contents.
- Whether it contains model artifacts, dataset material, mixed content, or remains unresolved.
- Evidence supporting that classification.
- Whether it affects the dataset-completeness conclusion.

Use existing manifests, exact artifact matches, or safe structural listings. No raw biological sequence inspection or model loading is required for this classification.

**Acceptance:** No unresolved container that could materially change the dataset-location or membership conclusion remains hidden behind a general “unopened” note.

A container can be excluded from the dataset search when sufficient evidence establishes its unrelated role. File size or a suggestive name alone is insufficient.

**5. Establish forget-versus-retain roles with documentary evidence.**

For each dataset version and split, identify the evidence assigning its role.

Keep separate:

- A dataset’s documented identity.
- Its configured role in a particular run.
- Whether actual use in that run is evidenced.
- Whether the observed evaluation cohort is established.

The same source can have different roles across runs. Preserve those relationships rather than applying a single global label.

**Acceptance:** Every required role assignment has a source-backed rationale. Mixed, conflicting, or unknown assignments cannot be promoted to confirmed forget or retain membership.

**6. Establish version and preprocessing provenance.**

Document the available chain:

```text

→ documented release/version
→ preprocessing implementation and configuration
→ produced dataset artifact
→ split/cohort manifest
```

For every link, identify the supporting source and what it establishes.

Required details should include, where applicable:

- Dataset release or revision.
- Preprocessing implementation identity.
- Relevant preprocessing configuration.
- Declared inclusion and exclusion rules.
- Artifact or manifest identity.
- Supersession or correction history.

**Acceptance:** Every provenance link necessary to identify the intended inputs is supported. A missing required link prevents acceptance; an inapplicable link requires a specific justification.

Do not reconstruct undocumented biological transformations or silently substitute a newer release.

**7. Establish split and cohort identity without overstating it.**

Record train, validation, and test identities separately.

Distinguish:

| Evidence | What it establishes |
|---|---|
| Configuration says “validation” | Intended split designation |
| Versioned split manifest | Declared split membership |

Record documented overlap checks and their actual scope. If overlap or independence has not been established, preserve that limitation.

**Acceptance:** The dataset and split identities needed for downstream provenance review are established. Any missing evidence about the actual evaluated cohort is explicitly assigned to the appropriate downstream dependency and prevents claims that the cohort is already verified.

T02 must not treat a split’s name as proof that it was untouched, independent, or actually used.
